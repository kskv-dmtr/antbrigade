# Сборка и выкладка

Astro 5, вывод — статика. Никакого рантайма на сервере: `dist/` можно
положить на любой хостинг, отдающий файлы.

## Что происходит по `npm run build`

1. **Astro собирает страницы.** `getStaticPaths()` в каждом `[slug].astro`
   разворачивает данные в файлы: 1100 релизов, 988 исполнителей, 617 лейблов,
   298 жанров, 76 клипов плюс шесть списков и 404. Итого 3086 файлов, около
   17 секунд.
2. **`postbuild` дописывает два файла:**
   - `make-static-config.mjs` кладёт в `dist` свой `vercel.json`;
   - `make-sitemap.mjs` собирает `dist/sitemap.xml`.

## Адреса без слеша

```js
build: { format: 'file' },
trailingSlash: 'never'
```

Внутри сборки страницы лежат файлами с расширением — `artists.html`. Наружу
Vercel с `cleanUrls` отдаёт их без него, а `.html`-адрес переправляет 308-м.

Отсюда две подпорки, о которых легко забыть:

- **канонический адрес** в `Base.astro` срезает расширение сам, иначе
  каноническим объявлялась бы ссылка на редирект — ровно то, ради чего
  canonical и ставят;
- **карта сайта** собирается из настоящих файлов и срезает расширение тем же
  правилом, поэтому разойтись им негде.

## Карта сайта

Своим скриптом, а не готовой интеграцией: зависимость ради тридцати строк, а
главное — она не знала бы про `format: 'file'`.

Дата берётся у самой свежей страницы, а не у каждой отдельно: сайт
пересобирается целиком каждый час, и обещать поисковику, что все три тысячи
страниц изменились час назад, — верный способ, чтобы карту перестали
принимать всерьёз.

Две страницы в карту не попадают: `releases.html` (перенаправление со старого
адреса каталога) и `404.html`.

## Переезд `/releases` → `/music`

Раздел каталога переименован 9 августа. Правило записано **дважды**:

- настоящий 308 отдаёт Vercel по `vercel.json`;
- астровский `redirects` кладёт в сборку страницу с `meta refresh`.

Второе — на случай, когда правила Vercel не читают: в локальной разработке и
при раздаче той же папки с Cloudflare Pages.

## Заголовки

| путь | кэш | почему |
|---|---|---|
| `/covers/*` | год, `immutable` | имя файла содержит идентификатор вложения и меняется вместе с картинкой |
| `/icons/*` | час, `must-revalidate` | имена постоянные: `icon-512.png` остаётся собой, даже когда картинка другая |
| `/manifest.webmanifest` | час | плюс явный `Content-Type` — без него часть браузеров игнорирует манифест |

Годовой `immutable` на иконках однажды уже оставил на телефонах июльскую
картинку после августовской замены. Отсюда и метка версии в адресе иконок в
`Base.astro`: другой адрес — другая запись в кэше. **Менять метку при каждой
замене иконок, и здесь, и в манифесте.**

Заголовки продублированы в `public/_headers` — это формат Cloudflare Pages,
файл копируется в `dist` как есть.

## Где это живёт

Хостинг — **Vercel**, и причина ровно одна: домен `*.pages.dev` недоступен из
России, тогда как `*.vercel.app` открывается. Cloudflare Pages остаётся
запасным вариантом, под него в проекте есть и `_headers`, и скрипт
`deploy:cloudflare`.

Канонический адрес — **с приставкой `www`**: голый `antbrigade.fun` отдаёт
308 на www-версию, и без приставки каждая страница объявляла бы каноническим
адрес, который тут же переправляет обратно. Если в Vercel основным сделают
голый домен — поменять `site` в `astro.config.mjs` и пересобрать.

## Как обновляется сайт

Обычно — сам. Бот коммитит данные раз в час (см. [[Синхронизация]]), Vercel
видит пуш и пересобирает.

Правки кода выкладывает владелец пушем в `main`. Ручной выкладки командой
почти не бывает, но она есть: `npm run deploy`.

## Установка на домашний экран

Манифест, иконки, мета-теги — всё на месте, приложение ставится. Service
worker для установки не нужен, Chrome убрал его из требований, **поэтому
офлайна нет** — только установка.

Две вещи, которые стоит помнить:

- приложение привязано к домену: установленное с `*.vercel.app` и с боевого
  домена — два разных приложения;
- на iOS кнопки установки нет, только «Поделиться → На экран „Домой“».

Ярлыки в манифесте ведут на адреса **без** слеша: со слешем каждый запуск
ярлыка стоил бы лишнего перенаправления.

## Сеть на машине владельца

У git в глобальных настройках стоит `http.sslbackend schannel`, и эта связка с
локальным прокси работает через раз. Пуш иногда падает с
`schannel: failed to receive handshake` — помогает повтор.

Оттуда же растёт то, что кадры клипов локально не качаются: см.
[[Синхронизация]].

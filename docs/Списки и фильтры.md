# Списки и фильтры

Пять страниц со списками устроены одинаково. Понимание этого места экономит
больше всего времени: почти каждая правка интерфейса попадает сюда.

## Главное правило

**Сервер отдаёт все записи сразу.** Фильтры ничего не подгружают и ничего не
удаляют — они прячут лишнее атрибутом `hidden`. Отсюда три следствия:

- страница работает без скрипта, просто без отбора;
- поисковик видит весь каталог;
- отбор мгновенный, сети не касается.

Цена — вес: `/music` несёт в разметке все 1100 релизов в обеих разметках,
строкой и плиткой.

Есть общая страховка: `[hidden] { display: none !important }`. Правило
браузера слабее любого авторского `display`, и без этой строки у всего, чему
задан свой `display`, атрибут молча переставал работать.

## Из чего состоит полоса управления

```
┌─ .sticky-bar ──────────────────────────────────┐
│ [ поиск                        ] [ List | Grid ]│
│ [ полоса кнопок ]        [ списки ] [ Reset ]   │
└────────────────────────────────────────────────┘
```

Полоса липкая, прячется при прокрутке вниз и возвращается при прокрутке
вверх. Порог в шесть пикселей нужен, чтобы она не дёргалась от инерционной
прокрутки.

Отдельная тонкость: список под полосой умеет внезапно укорачиваться — выбрали
редкую букву, и от девятисот имён осталось два. Страница становится короче
экрана, прокручивать нечего, новых событий не приходит, и спрятанная полоса
остаётся спрятанной навсегда. Ловится это `MutationObserver`-ом по самой
правке разметки, а не `ResizeObserver`-ом: его вызовы привязаны к отрисовке
кадров, а мутации приходят всегда, в том числе в фоновой вкладке.

## Чем сортирует

| страница | пункты |
|---|---|
| `/music` | Newest first, Oldest first, Artists A → Z, Artists Z → A, Albums A → Z, Albums Z → A |
| `/videos` | те же шесть, только вместо альбомов названия роликов |
| `/artists` `/labels` `/genres` | A → Z, Z → A, Most releases |

У каждой оси обе стороны. Стрелка в подписи одна и та же везде, поэтому
направление читается одинаково.

`/music` и `/videos` открываются с `Newest first`, списки имён — с
`A → Z`. К этому же пункту возвращает `Reset`, и по нему же считается,
тронута ли сортировка. Порядок с сервера всегда совпадает с этим пунктом:
он же остаётся, когда скрипт не выполнился.

Сортировка по дате на `/videos` появилась 29 августа 2026, вместе с датой
выхода клипа в Notion; до неё сортировать было не по чему.

**Порядок с сервера — это первый пункт своей страницы**, и скрипт держит его
отдельным массивом, чтобы возвращать без пересортировки.

Сортировка устойчива, поэтому при равных ключах сохраняется порядок с
сервера: у клипов одного исполнителя в `Artists Z → A` названия остаются от
A к Z, а не переворачиваются вместе с именами.

## Что чем отбирает

| страница | полоса кнопок | списки |
|---|---|---|
| `/music` | тип релиза | жанр и год (пачкой, со счётчиками), сортировка |
| `/videos` | вид ролика | сортировка |
| `/artists` `/labels` `/genres` | первая буква (A–Z и #) | сортировка |

Подписи кнопок и их порядок заданы в коде, а **ключом фильтра остаётся
значение из Notion**: там типы записаны в единственном числе, а на кнопке
читается множественное. Тип, которого нет в списке подписей, появится в
полосе сам — просто в конце и под своим именем.

Порядок тоже свой: сначала три формата по убыванию длины — `Album`, `EP`,
`Single`, — потом две пометки. По алфавиту редкая `Collaboration` с двумя
десятками записей вставала бы перед `EP`, которых почти две сотни.

## Полоса кнопок и список — один выбор

На узком экране полосы кнопок не помещаются, и вместо них показывается
выпадающий список. **Оба контрола лежат в разметке всегда** — сайт
статический, разметка одна на все ширины, — а лишний прячет медиазапрос.

Значение у пары общее: обработчики зовут одну функцию (`setType`, `setKind`,
`setLetter`), и что бы ни выбрали, второй контрол переставляется следом.
Человек может повернуть телефон, и выбор должен пережить смену ширины.

Пороги подмены разные, потому что полосы разной длины:

| полоса | нужно ширины | подменяется ниже |
|---|---|---|
| тип релиза | 420 px | 640 px |
| вид ролика | 330 px | 640 px |
| первая буква | 756 px | **840 px** |

Алфавит из 28 кнопок перестаёт помещаться в колонку уже при кадре в 812
пикселей — намного раньше остальных, поэтому порог у него свой. Пока его не
было, между 641 и 811 полоса вылезала за правый край колонки под самый край
экрана: сжиматься ей нечем, прокрутки на этих ширинах нет, а перенос
`.filters` не спасает — переносится она целиком.

## Ряд списков на узком экране

Все списки стоят в одну строку, и она **осознанно уезжает за край экрана**.
Вчетвером им нужно около 520 пикселей при 343 доступных; ужать до строки не
получается ни полями, ни кеглем — проверено, тройка держалась только на 375 и
шире, а на 360 год уже переносился. Перенос же занимал два этажа полосы.

Строка идёт от края до края экрана, а не обрывается за шестнадцать пикселей
до него: обрыв под самой рамкой читается как «дальше есть ещё». Поле
возвращается изнутри, поэтому первый список начинается вровень с поиском.

За края уехал и фон липкой полосы — иначе по шестнадцать пикселей у каждого
края оставались непокрытыми, и сквозь них при прокрутке ехали обложки.

## Ширина закрытого списка

Считает скрипт компонента `Select`, по выбранному пункту. Но до его
выполнения браузер меряет кнопку по **самому длинному** пункту, и она
заметно шире: тип релиза 158 против 76, вид ролика 181 против 76, сортировка
на списках имён 151 против 90. Это и моргало.

Лечится стартовой шириной в CSS под ту подпись, с которой страница
открывается:

```css
.select--strip select { width: 76px; }   /* All */
.select--az    select { width: 90px; }   /* A → Z */
.select--narrow select { width: 128px; } /* All genres */
```

Пересчёт после загрузки шрифта тут ни при чём: запасной моноширинный даёт
разницу в два пикселя, её не видно.

Потолок ширины (`max-width`) оставлен только жанрам: их 298, и самый длинный
требует 226 пикселей. Остальным он только вредил — резал подписи, хотя место
в строке было.

## Reset

Появляется, когда хоть что-то уведено от значения по умолчанию, и чистит всё
разом: поиск, полосу, списки, сортировку. Есть на четырёх страницах из пяти.

**На `/music` его нет** — с 29 августа 2026 каждый контрол там сбрасывается
сам: жанр и год крестиком на своей кнопке, тип — кнопкой `All` в полосе,
сортировка — своим первым пунктом, поиск — клавишей. Отдельная кнопка, чистящая
всё разом, оказалась третьим способом сделать то же самое.

## Горячая клавиша

Косая черта фокусирует поиск, `Escape` отпускает — как на GitHub. Сочетания с
модификаторами не трогаем, они принадлежат браузеру; и если человек уже
что-то набирает, косая должна набраться, а не увести фокус.

`Escape` только снимает фокус и **не стирает набранное**: иначе он рушил бы
выборку, которую человек собирал.
